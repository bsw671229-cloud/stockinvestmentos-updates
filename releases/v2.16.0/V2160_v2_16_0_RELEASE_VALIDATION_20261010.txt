Implementation:
Optional observation callbacks collect existing raw results in the current browser
session only. Context includes client identity/object, mode, all query inputs and
app version. Detailed result metadata must match the sanitized market report.
Every check/item timestamp must be within five minutes; future timestamps fail.
Connection/view/range/input changes clear details. Expiration is checked at rerun
and again at navigation; there is no background polling or timed screen refresh.
Retried markets get new detail and selection state. A successful retained market
keeps its original timestamp/record/selection. Failed new balance results never
reuse a prior successful holdings table. No shared cache or new persistence.
Each market shows its quote, native-currency buying power, original check times,
balance scope and named holdings. KRW/USD are separate and are never summed.
Local substring search covers name/code/exchange. Search filters the displayed
table; the explicitly labelled selection box lists all holdings independently.
The selectbox and separate navigation button are required. Invocation rechecks
the connection, source record, current report and latest selected option.
Only market/exchange/symbol transfer; previous order/precheck authority is cleared.
OTCB remains read-only, and NAS is normalized to NASD for precheck.
Incomplete balances do not expose selectable holdings.
Full-query progress has six phases; failed-market retry has three per market.
Callback failures do not interrupt the inquiry sequence. Existing request order,
adapter routing, rate controls and failed-market retry semantics are unchanged.
Downloaded reports keep the existing sanitized schema and exclude raw data,
account identity, keys, holdings, symbols, prices and cash amounts.
